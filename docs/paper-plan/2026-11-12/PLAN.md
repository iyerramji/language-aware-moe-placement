# Balanced language-aware expert placement for multilingual MoE serving

**One-page paper plan · 12 November 2026 · Draft for Raj**

**Question and lead figures.** Can language-aware placement reduce communication and decode latency while keeping GPU load balanced? Lead with the **4/8-GPU locality–imbalance curves**, followed by the **exact request-shuffle control**. On Indic-only traffic, real language groups beat shuffled groups by **6.80 points on Sarvam Wikipedia, 6.95 on Qwen3 FLORES and 5.68 on Sarvam FLORES** in remote expert-hit reduction (4 simulated GPUs, two extra expert copies per GPU per MoE layer). These are recorded-count results, not measured bytes or speedups.

**Method and scope.** Use fit-only, per-language/per-layer routing counts to choose request home GPUs, expert placement and bounded replication. Sweep the primary-load cap to expose the locality–balance trade-off; choose candidate plans using fit data, then freeze them for evaluation. Keep every logical expert accessible and model/router weights unchanged. Current caps constrain primary fit load before copying; measure final load after copying rather than claiming a runtime balance guarantee. Retain the existing three datasets, full and Indic-only mixes, length sensitivity and sentence-matched FLORES controls. The shuffle is conditional on fit-selected group capacities, not a pipeline-wide significance test. No new Qwen3 Wikipedia collection or language-family study is needed.

**Measured experiment — next, not yet run.** Implement one serving-engine path and compare our balanced placement with its documented default placement on **4 and 8 real GPUs**, targeting the brief’s L40S PCIe setup. Record the actual interconnect topology, engine/version, precision and batching settings. Use identical prompts, generation lengths, arrival schedules and GPU resources. Include an equal-replica-memory language-blind comparator to separate language/layout benefit from extra memory; report total memory and KV capacity for every configuration. Obtain evaluation prompts through the permitted dataset access route: the supplied per-sequence histograms contain no text and cannot drive live decoding.

Measure **dispatch/combine all-to-all bytes**, communication time, decode inter-token latency (p50/p95/p99), throughput and per-GPU final expert work/utilization. Report prefill and decode separately, normalize decode bytes by generated tokens, and state whether byte counters measure logical payload or physical-link traffic. Count each transfer once under a declared convention. Use warm-up, paired workloads and repeated runs; retain variability and output-correctness checks. The decisive result is lower measured bytes and decode latency against default at matched offered load, without hiding overload or memory costs. Fewer remote hits alone do not establish this.

**Rebuild experiment including migration.** Replay declared gradual, abrupt and alternating traffic changes. Sweep update intervals in **input tokens served**, preserving the earlier unit and also reporting generated tokens. Compare static placement, periodic rebuilding and a clearly labeled fresh-plan reference. Charge each update for profiling/planning, actual expert-weight transfers, synchronization, temporary memory and serving disruption. Measure migration bytes, update duration and latency during updates; report total communication as serving plus migration bytes. Find the intervals where measured serving savings outweigh update overhead over the same token horizon. Existing 524,288/131,072-token retention thresholds exclude those costs and are not deployment recommendations.

**Deliverable and decision.** Produce the two lead figures, measured bytes/latency comparisons and a migration-inclusive rebuild curve. Mark mathematically infeasible caps explicitly (Sarvam FLORES, 8 GPUs: 1.1/1.25). If locality fails to improve serving latency, report that limit. The proposed contribution is the demonstrated value and practical trade-off of language-aware balanced placement; novelty and a systems speedup remain to be established.
